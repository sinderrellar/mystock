# 研究报告库「研究过程」追溯 —— 去掉任务列表、研究条目并入报告库

## 背景 / 需求（老板 2026-09-04）

上一版在「深度研究」页加了一个独立的「任务列表」，老板反馈方向不对，要求：

1. **去掉任务列表**。
2. 发起研究后，直接在**研究报告库**里新增一条，状态标记「研究中」。
3. 未研究完成的条目 → 点进去是 **wecode session 的「研究过程」**（实时）。
4. 研究完成的条目 → 点进去是**结果报告**，报告右上角加一个「📋 研究过程记录」链接。
5. 历史报告（无 session_id）→ 该链接内容为空（即不显示链接）。

## 改了什么

### 后端

- `scripts/debate_engine.py`
  - `run_agent_with_session(prompt, timeout, on_session)`：用 `Popen` 非阻塞启动 wecode，轮询 `~/.claude/projects/<slug>/` 目录**尽早捕获新会话文件**（约 2-5s），捕获到 `session_id` 立即回调 `on_session`（供 worker 落库，让前端在 running 期间就能拉到过程）。
  - `extract_session_process(session_id)`：把会话 JSONL 提炼成可读 markdown（🧠 思考 / 🔧 调用工具 / 文本块），带 `[0-9a-zA-Z-]+` 防路径穿越，返回 `{session_id, exists, done, markdown}`。
- `scripts/research_engine.py`：`run_research` / `run_verdict` 增加 `on_session` 回调参数，改用 `run_agent_with_session`，返回值带 `session_id`。
- `scripts/research_tasks.py`：`_execute_task` 增加 `_on_session` 回调，把 `session_id` 实时 `$set` 到任务文档；`_run` 完成时把 `session_id` 一并写入。
- `scripts/api_server.py`
  - `GET /api/research/reports`：返回 `{reports, in_progress, types}`；`reports` 每项附 `session_id`（由 done 任务映射），`in_progress` 为 queued/running 任务（含 `session_id`）。
  - 新增 `GET /api/research/process/{session_id}`：读研究过程 markdown。

### 前端（`web/src/pages/ResearchPage.jsx`）

- 删除 `TaskList` 组件、`getResearchTasks` 导入、`TASK_TYPE_LABEL` / `TASK_STATUS` 常量。
- 新增 `ProcessPane`：双模式——`task`（研究中，轮询任务状态同步最新 session_id + 轮询过程，done 时回调 `onTaskDone`）、`sessionId`（静态展示研究过程）。
- 重写 `LibraryPanel`：从 `getResearchReports()` 同时取 `reports` + `in_progress`；`in_progress` 条目以「研究中」标记排在最上；点 in-progress 条目 → `ProcessPane`；点完成报告 → 报告 markdown + 有 session_id 才显示「📋 研究过程记录」链接；无 session_id 的历史报告不显示链接。任务完成后自动刷新并切换到结果报告。
- `web/src/styles.css`：删除 `.task-list` / `.task-item` / `.ti-*` 样式。

## 为什么这样改

- **研究过程 = wecode 的 Claude Code 会话 JSONL**（`~/.claude/projects/<cwd 转 slug>/<sessionId>.jsonl`），是唯一真实可回溯的「过程」。
- 关键难点是**尽早拿到 session_id**：旧 `subprocess.run` 阻塞到结束才知道 session_id，前端无法在 running 期间展示过程。改用 `Popen` + 目录轮询，会话文件出现即落库。
- 前端 `ProcessPane` 用 `useRef` 持最新 `onTaskDone` 回调、用内部 `taskState` 轮询任务拿最新 `session_id`，避免「排队中任务 session_id 为 null、切 running 后过程视图永远空白」的坑，也避免回调引用变化导致轮询 effect 反复重建。

## 怎么验证

1. `npm run build` 通过（312 modules，无残留 `getResearchTasks`/`TaskList`/`.ti-*` 引用）。
2. 后端重启（PID 1873 → 10305）后 `/api/auth/config` 返回 200。
3. 三个新端点均 401（已注册、需鉴权，非 404）：
   - `/api/research/reports`
   - `/api/research/process/{session_id}`
   - `/api/research/reports/{name}`
4. 直接调用验证底层逻辑：
   - `research_engine.list_reports()` 返回 21 份报告，字段含 `type_label/date/age_days/fresh/validity_days`。
   - `extract_session_process` 对真实会话返回 `exists=True done=True`（markdown 14k~113k 字符），非法 id `../../etc/passwd` 被正确拒绝（`exists=False`）。

## 局限

- **未做端到端真实研究闭环验证**（需真跑一次 wecode 2-9 分钟并落一份真实报告）；上述验证覆盖了构建、端点注册与底层函数，但「触发研究 → 研究中条目 → 过程实时刷新 → 完成后切换报告」的完整链路未实测。如需，可发一条测试研究触发验证。
- 历史报告（含本会话早期跑的 `investment_research_中国移动_2026-09-04.md`，其任务 `3df75e88` 在 session_id 落库逻辑上线前生成、session_id=None）无「研究过程」链接，符合老板「历史链接内容为空」的预期。
- 周期/CLI 方式跑的研究（无 per-user 任务）不会有 session_id 映射，链接同样为空。
