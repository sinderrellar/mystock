# 行业动量热力换手率缺失修复

日期：2026-09-08

## 为什么改

老板问「行业雷达中的行业动量热力数据对吗？」。排查后发现：**核心数据（信号日期/广度/5·20·60日涨幅/RSI/PE中位）都正确且新鲜**，但有一个真实缺陷——**换手率全市场缺失**，导致动量分被系统性压低、状态标签整体偏严。

## 根因

1. `stock_basic_info` 里 `display_market='A股'` 共 5555 只，`turnover_rate` 字段存在但**全为 None**。
2. 根因在 `import_universe_light`（`data_import_pipeline.py`）用 `ak.stock_zh_a_spot()`（新浪源）导入，实测该接口返回的列只有 `代码/名称/最新价/涨跌额/涨跌幅/买入/卖出/昨收/今开/最高/最低/成交量/成交额/时间戳`，**没有「换手率」列**，所以 `row.get("换手率")` 恒为 `None`。

## 影响

- `sector_radar.compute_heatmap` 的动量分公式 `0.25*广度 + 0.30*20日 + 0.20*RSI + 0.15*换手 + 0.10*5日`，换手项对每个行业都是均匀 0，**分数被压缩到 [0, 0.85] 区间**。
- 阈值 `hot=0.7 / warm=0.4`（config 实测）按 [0,1] 设计，导致 🔥领先 实际需 82% 满分（本应 70%）、📈改善 需 47%（本应 40%），**部分该 🔥/📈 的行业被降级**。
- 无数据污染，其余维度正常。

## 改了什么（两处，一止血一补数据）

### 1. 止血：`scripts/sector_radar.py` `compute_heatmap`
换手率缺失（`turnover_vals` 为空）时，剔除换手项并把剩余权重归一化到 [0,1]：

```python
has_turnover = bool(turnover_vals)
w_b, w_r20, w_rsi, w_to, w_r5 = 0.25, 0.30, 0.20, (0.15 if has_turnover else 0.0), 0.10
w_total = w_b + w_r20 + w_rsi + w_to + w_r5
momentum_score = (b*w_b + r20*w_r20 + rsi*w_rsi + to*w_to + r5*w_r5) / w_total
```

有换手率时 `w_total=1.0`，行为与原来完全一致；缺失时把分数拉回 [0,1]，阈值立即恢复准确。

### 2. 补数据：`scripts/data_import_pipeline.py` 新增 `import_turnover_rate`
用 Tushare `daily_basic`（按 `trade_date` 单次拉全市场约 5500 只）回填 `turnover_rate`/`turnover_rate_f`/`volume_ratio` 到 `stock_basic_info`。

- 注册 CLI：`python3 data_import_pipeline.py import-turnover-rate`
- 接入 `import-all`（每周日全量导入），列为第 2/7 步，保证换手率持续更新。

## 局限 / 待办
