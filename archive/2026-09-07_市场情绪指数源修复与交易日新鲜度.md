# 市场情绪指数源修复 + K线新鲜度改交易日口径

## 背景 / 需求（老板 2026-09-07）

老板反馈组合全景「很慢」，追问「有需要实时计算的数据吗」。上一轮已定位并修掉 `sector_radar` config 热循环重复读盘 bug（13.8s→6.2s，见 `archive/2026-09-07_组合全景提速_config缓存修复.md`）。剩余 ~6s 里有两个真实 bug，老板拍板「好的，改吧」：

1. `_data_age_days` 用**自然日**算新鲜度 → 周五(09-04)→周一(09-07) 被误判「3 天过期」，明明只隔 1 个交易日，导致 `get_bars` 无谓触发 Yahoo 兜底。
2. `get_market_sentiment` 的指数源用 **Yahoo 符号**（`000001.SS` 等），实测全部 `available=False`。

## 根因

### 1. Yahoo 在本环境整体 403（比「符号写错」更底层）

实测 `query1.finance.yahoo.com/v8/finance/chart/...` 对指数（`000001.SS`/`399006.SZ`/`000300.SS`）**和个股（`000001.SZ`/`399001.SZ`）一律返回 `HTTP 403 Forbidden`**。所以 `_get_yahoo_bars` 无论符号对不对都返回 `[]`，情绪三指数全空、`available=False`，且失败路径不写缓存 → 每次 review 都白跑一遍（第 2 次仍 3.036s）。

这是**环境级网络封锁**，不是符号格式问题，改符号无解，只能换数据源。

### 2. 自然日新鲜度误判

`_data_age_days` 原实现按 `(today - data_date).days` 算，跨周末就 +3，超过阈值 `age > 1` 触发 Yahoo 兜底。周五收盘数据周一早盘就被判「过期」。

## 改了什么（`scripts/market_data_provider.py`）

### A. `_data_age_days` → 交易日口径

```python
def _data_age_days(data_date):
    dt = _parse_date(data_date)
    if dt is None: return None
    today = _utc_now().date(); d = dt.date(); days = 0
    while d < today:
        d += timedelta(days=1)
        if d.weekday() < 5: days += 1   # 只数工作日
    return float(days)
```

### B. `get_market_sentiment` → 腾讯指数 K 线源 + 日级缓存

- 新增 `_get_tencent_bars(symbol, days)`：走腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get`（字段顺序 `[date, open, close, high, low, volume]`，返回倒序最新在前，形状对齐 `_get_yahoo_bars`）。
- 指数映射改为腾讯符号：上证指数=`sh000001`、创业板指=`sz399006`、沪深300=`sh000300`。
- 保留模块级日缓存 `_MARKET_SENTIMENT_CACHE`（情绪基于日线盘中不变，一天拉一次，跨 review 复用）。

## 怎么验证

1. `py_compile` 通过。
2. `_data_age_days`：`2026-09-04→1.0`、`09-03→2.0`、`08-28→6.0`（均为交易日，跨周末不再虚高）。
3. 腾讯 K 线：三指数各 30 条、最新 `2026-09-07`（上证 3932.7 / 创业板 3398.68 / 沪深300 4575.02）。
4. `get_market_sentiment`：**第 1 次 1.16s、`available=True`**（此前 6.2s + `available=False`）；**第 2 次 0.000s 命中缓存**。
5. 空仓 `review()`：**13.8s → 6.2s → 2.0s**（剩余 2s 是资金流东财准实时接口，已随情绪一起按日缓存）。
6. 后端重启（PID 26643 → 31597），`/api/health` 200。

## 影响评估 / 遗留

- **无数据污染**：只改数据读取来源与新鲜度判断，不写任何库表（`_get_tencent_bars` 不回写 Mongo，指数本就不在个股日线缓存里）。
- **遗留（超出本次范围，已告知老板）**：`get_bars` 的个股 Yahoo 兜底（`scripts/market_data_provider.py:686`）同样受 Yahoo 403 影响——但只要每天跑 precompute、Mongo 日线不超 1 个交易日，`get_bars` 不会触发兜底（交易日口径已让 09-04 数据周一不再「过期」）。若未来 precompute 停 3 天以上，个股 K 线兜底需另找非 Yahoo 源（腾讯同款 `fqkline` 对个股也适用，可复用 `_get_tencent_bars`）。
