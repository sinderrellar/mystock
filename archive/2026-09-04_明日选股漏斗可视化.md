# 明日选股（buy_plan）分层漏斗可视化 + 动态筛选

日期：2026-09-04

## 改了什么

把 `/buyplan` 页从「静态表 + 几段计数」升级为**可交互的分层漏斗筛选器**，老板可在页面上手动调每层阈值，股票列表实时联动。

### 后端 `scripts/buy_plan.py`

- `run()` 改为**无条件**给所有 scored 项算 `alpha_score` + 打 `strategy_tags`/`tag_*`（原先 `cycle<0.20` 的项不打标签）。
- 给每项标 `in_portfolio`（是否已持仓）。
- 新增 `pool` 字段返回**完整打分池**（原始 alpha_score，不降权），前端据此动态筛选。
- `recommendations` 保持原语义（top N + 已持仓 ×0.5），用 `dict(s)` 浅拷贝降权，**不污染 pool**。
- `scripts/api_server.py` 无需改动（`_jsonable(result)` 自动带上 `pool`）。

### 前端

- 新增 `web/src/buyplan.js`：`DEFAULT_FILTERS`（5 层默认参数）、`applyFilters(pool, filters)`（L1→L4 顺序过滤 + L5 排序截断，返回每层存活数）、`distToMA20`、`loadFilters`/`saveFilters`（localStorage 持久化）。
- 重写 `web/src/pages/BuyPlanPage.jsx`：横向漏斗图（每层宽度 ∝ 存活数、标注 ↓ 掉队数）、5 层筛选面板（滑杆 + chips + 开关 + 下拉）、存活候选表（点行高亮）、点选后弹出 6 维因子雷达（SVG，动量/周期/拐点/价值/成长/质量）。
- `web/src/styles.css` 追加漏斗/滑杆/chip/开关/雷达样式（走 `:root` 变量）。
- `web/smoke/entry.jsx`：明日选股断言从「明日候选」改为「分层漏斗 + 筛选面板 + 策略标签」。

### 5 层参数口径（因子模型，不用旧 pass/fail 规则）

| 层 | 可调参数 |
|---|---|
| L1 海选 | 市值下限(亿)/成交额下限(万)/PE 区间（只能收紧，服务端已初筛） |
| L2 趋势 | 趋势状态多选、5/20/60 日收益区间、站上 MA20 |
| L3 策略 | 动量/周期/拐点/综合因子下限、策略标签（命中任一即留） |
| L4 入场 | RSI 区间、距 MA20% 区间、量价信号多选 |
| L5 排名 | alpha 权重三滑块、排序字段、Top N、已持仓降权开关 |

## 为什么这样改

- 老板诉求「每一层可视化 + 自己调策略 + 动态筛选」，本质是交互式漏斗。后端只吐 top N 会导致数据不足，故先把完整打分池 `pool` 吐出来。
- 选**纯客户端筛选**：一次取 pool（≤200 只）后所有阈值调整即时生效，无需每次重算 MongoDB/因子。
- 选**因子模型口径**：`buy_plan.py` 已是 v3 因子模型，旧 5 层 pass/fail 规则在 `buyplan.md` 里已被论证会误杀主升浪牛股。

## 怎么验证

- 后端：`venv/bin/python scripts/buy_plan.py --top 3 --json` → `pool` 190 只，字段含 `alpha_score`/`in_portfolio`/`strategy_tags`/`factor_scores`；`recommendations` 仍 top N。
- 过滤逻辑单测（Node）：`applyFilters` 对合成池验证了 cycle 默认过滤（cycle<0.2 被滤）、已持仓降权后重排序、`distToMA20` 计算正确。
- 前端：`cd web && npm run build` 通过（无语法/JSX 错误）。

## 已知边界

- 海选层只能**收紧**（市值/成交额/PE 的服务端下限 mv≥50亿、amount≥5000万、pe∈(0,200) 已定死）；想放宽看更小/更冷门标的需后端重查，属后续增强。
- `pool` 是一次性快照（≤200 只、当日因子日期），非实时行情逐 tick。
- 部分标的价值/成长/质量因子可能为 0（该组未计算），雷达会如实显示 0 维。
