# 2026-09-04_修复工程可运行性与数据导入

## 改动内容

### 1. 修复 venv Python 调用路径
- `venv/bin/python` 是相对软链 `python -> python3`，在 `scripts/` 下执行相对路径 `venv/bin/python` 会找不到。
- 重新建立软链 `ln -sf python3 python`，确保从项目根目录执行 `venv/bin/python` 可用。
- 实际验证：`venv/bin/python -c "import sys; print(sys.executable)"` 返回 `/data2/liuyu20/mystock/venv/bin/python`。

### 2. 补齐缺失依赖
- 原 `requirements.txt` 缺少运行必需包，且 venv 内缺 `scikit-learn`、`tushare`。
- 安装：`scikit-learn 1.6.1`、`scipy 1.13.1`、`tushare 1.4.29`、`anthropic 0.125.0` 及依赖。
- 更新 `requirements.txt`，补充实际代码用到的依赖：`numpy, scipy, scikit-learn, PyYAML, pymongo, dnspython, akshare, tushare, requests, pandas, beautifulsoup4, openpyxl, lxml, tabulate, tqdm, anthropic`。

### 3. 修复 `data_import_pipeline.py data-check` 空库崩溃 + 信号缓存集合识别
- 原代码对 `"无"` 字符串直接 `datetime.strptime`，空 MongoDB 下会 `ValueError` 崩溃。
- 在 A股日线、信号缓存两处改为 if/else 分支，空库时输出 `status=🔴`、`age_days=?`，并提示需要运行导入。
- 信号缓存检查兼容新旧集合：`precompute_history.py v3` 写入 `stock_factors`/`stock_trends`/`stock_meta`，老资金流/一致预期写入 `stock_signals`。`data-check` 现在以 `stock_factors.trade_date` 作为信号新鲜度依据。

### 4. 修复 `import-universe-quotes` 在轻量基础信息下 0 命中
- `import-universe-light` 只写入轻量字段（无 `total_mv`、`pe`），导致原查询 `"total_mv": {"$gte": 5e9}, "pe": {"$gt":0, "$lt":50}` 一只都选不到，日线无法导入。
- 改为：先尝试严格查询（市值+PE）；命中数不足 `limit/2` 时，降级为仅按 `display_market` + `market` + `latest_amount` 过滤，保证系统能导入日线。

### 5. 创建 `data/portfolio.yaml`
- 原仓库只有 `data/portfolio.example.yaml`，系统默认读 `data/portfolio.yaml`。
- 复制模板并清空 `positions`/`watchlist`，避免 `portfolio_strategy review` 使用示例假持仓。
