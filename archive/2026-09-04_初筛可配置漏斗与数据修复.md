# 明日选股：初筛数据修复 + 初筛做成可配置漏斗 + 漏斗如实化

日期：2026-09-04

## 背景

老板连续两个诉求：
1. 「全市场初筛为啥只有 1371 条」——排查发现初筛被两个数据问题压低。
2. 「初筛也做成漏斗，然后用户可配置」——把 Layer0 初筛从后端硬编码的一步，变成前端可配置的逐级漏斗。

## 改了什么

### 一、数据修复（两层根因）

**根因 A：826 只股票 `market` 字段误标为「A股」**
- `_a_board()`（在 `data_import_pipeline.py` 与 `factor_data_import_service.py` 两处）代码段映射缺了创业板 301/302、北交所 920、主板 003，导致这些股票被归到 `market='A股'`。
- 修正两处 `_a_board()`，并把 826 只误标文档按代码段订正：创业板 469、北交所 341、主板 16；订正后 `market='A股'` 剩余 0。

**根因 B：3262 只（universe_light_sina 轻量导入）缺 total_mv / pe**
- 轻量导入只写 code/name/close/latest_amount/industry，没有总市值/PE，被 `市值≥50亿 + PE∈(0,200)` 初筛静默排除。
- 新增 `scripts/backfill_basic_fields.py`：用腾讯行情 `qt.gtimg.cn` 批量抓取（沪 sh / 深 sz / 北交所 bj 三种前缀，f39=PE、f45=总市值(亿)、f46=PB），批量 50 只/请求，只 update_one `$set`（禁 delete），幂等，打 `valuation_source` 标记。
- 全量补全 3202 只（+ 冒烟 60 = 3262），失败 0，剩余缺失 0。全市场 5555 只现全部具备 total_mv + pe。

**修复效果（Layer0 初筛真实漏斗）**：
```
全市场 5555 → 板块 5214 → 成交额 5206 → 市值≥50亿 3208 → PE∈(0,200) 2299 → 剔除ST/价格 2241
```
（修复前该链路在「市值」这步因为 2446 只缺市值被静默砍到 1989，最终 1371。）

### 二、初筛做成可配置漏斗（前端 + 后端）

- `scripts/buy_plan.py`：新增 `_get_universe()`，返回全部 active 股票的基础字段（code/name/close/pe/pb/total_mv/latest_amount/market/display_market/industry/industry_code），并在 `run()` 返回里加 `"universe"`。初筛阈值不再由后端定死，前端拿到全市场后自行逐级筛选。
- `web/src/buyplan.js`：
  - `DEFAULT_FILTERS` 增加 L0 初筛字段：`markets`（默认主板/创业板/科创板）、`excludeSt`、`priceMin/priceMax`；`BOUNDS` 增 `price`；新增 `MARKETS`。
  - `applyFilters(universe, pool, f)` 重写：漏斗头部如实展示「全市场 → 板块 → 成交额 → 市值 → PE → ST/价格 → 有因子 → 趋势 → 策略 → 入场 → 入选」，初筛每级都可配置。
- `web/src/pages/BuyPlanPage.jsx`：
  - 用 `data.universe` 驱动初筛；`LAYER_KEYS.screen` 扩展；L1 海选层改名「L0 初筛」，新增板块多选、成交额/市值/PE/价格下限上限、剔除 ST 开关。

## 为什么这样改

- 初筛阈值原来是后端 `config_complete.yaml` 里定死的（50亿/5000万/PE0-200/3板块），用户只能收紧、看不到真实掉量。老板要「初筛也做成漏斗 + 可配置」，所以把全市场基础信息下放到前端，由前端逐级过滤，既可视化每一级掉多少，又能任意放宽/收紧。
- 漏斗「如实化」：头部不再用被压低的 1371 冒充全市场，而是从 5555 全市场起，每一级掉量可归因到具体阈值。

## ⚠️ 发现的关键阻塞（需老板决策）

排查中发现**因子数据管道是坏的**，导致漏斗「有因子」及以下全为 0：

- `daily_quotes` 集合**为空（0 条）**——precompute_history 的输入源，没了它无法重算因子。
- `stock_factors`（293 条）/`stock_trends`（292 条）/`stock_meta`（293 条）是**旧的、局部的**数据，且这 293 只与 buy_plan 按「成交额 top200」挑选的富集池几乎零重叠（top200 ∩ 因子 = 0）。
- 结果：`run()` 里 `③ 因子: 200 → 0 只`，`pool=0`、`recommendations=0`。

这不是本次改动引入的（本次只动 basic_info 的 market/total_mv/pe 与 buy_plan 的 universe 返回），但会挡住漏斗出结果。需老板确认是否要我继续：先跑 `data_import_pipeline.py import-universe-quotes` 补 `daily_quotes`，再跑 `precompute_history.py --date today` 重算全市场因子。

## 已知边界

- 前端初筛的 PE 用闭区间 [0,200]（滑杆语义），后端 Layer0 用的是开区间 (0,200)，PE 恰好等于 0 或 200 的极少数股票会有 ±几只的差异；前端为初筛口径的唯一来源，影响可忽略。
- `universe` 每次 `/buyplan` 返回约 1.6MB，页面一次性加载；若后续嫌重可拆分页/精简字段。
