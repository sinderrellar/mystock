# 市场情绪：上证指数现价被按日缓存冻结的修复

日期：2026-09-08

## 为什么改

老板反馈「组合全景市场情绪板块，上证指数还是 3932」（实时价应是 ~3946）。

排查后定位真根因：`get_market_sentiment()` 的结果整体按**日**缓存（`_MARKET_SENTIMENT_CACHE` 以 `YYYY-MM-DD` 为 key）。服务在**盘前**（今天那根日线 bar 还没出来时）第一次算情绪，腾讯日线接口此时最新 bar 是**昨收 3932.70**，于是 `latest_close=3932.70` 连同趋势一起被写进今天的缓存；之后一整天都命中这条缓存，**现价永远停在盘前的昨收，不再更新到盘中实时价 3946.99**。

上一轮的「趋势与实时价分离」只把 5日/20日/波动改成用已收盘日线，没动 `latest_close`（仍是 `closes[0]`）——盘前冻结的问题依旧。本轮补上现价刷新。

## 改了什么

### `scripts/market_data_provider.py`

1. 新增模块级常量 `_INDEX_SYMBOLS`（指数名 → 腾讯 symbol），原来函数内局部 `indices` 字典上提，供「计算」和「命中缓存」两个分支复用。
2. 新增模块级短缓存 `_INDEX_QUOTE_CACHE: symbol -> (ts, price)`，TTL 60s——现价盘中随时变，不能按日冻结。
3. 新增方法 `_index_realtime_quote(symbol)`：走腾讯实时接口 `qt.gtimg.cn/q=<symbol>` 取现价 `fields[3]`，60s 短缓存，失败返回 `None`（调用方保留原值，不回退成 0）。
4. `get_market_sentiment()` 命中日级缓存时，**逐个指数刷新 `latest_close`**（趋势/波动/mood 仍按日缓存不变），再返回。

### 未改前端

前端上一轮已把面板改为「现价 / 5日 / 20日」并加「现价」标签，本轮后端修好后无需再动。

## 怎么验证

1. `py_compile` 通过。
2. 直接跑 `MarketDataProvider().get_market_sentiment()`（2026-09-08 盘中）：
   - 首次：上证 `latest_close=3946.99`、5日 -1.34、20日 -0.85、波动 0.82；
   - 手动把缓存里 `latest_close` 改成 3932.70 模拟盘前冻结，再次调用 → **现价刷回 3946.99**，趋势不变（-1.34/-0.85/0.82）；
   - 结论：命中缓存时现价能实时刷新，趋势保持稳定。
3. 重启 `api_server`（旧进程 10408 持旧代码与陈旧 `_MARKET_SENTIMENT_CACHE`），新进程 28086 启动正常，`/api/auth/config` 返回 200、`dev_user` 仍为空（CAS 登录流程不变）。

## 局限 / 待办

- **现价刷新粒度受上游 portfolio 缓存约束**：`get_market_sentiment` 每被 `review()` 调用一次才刷新现价，而 `_get_portfolio` 有约 3 分钟缓存，故现价约 3 分钟一跳；对「情绪面板」的定位够用，不是逐秒行情。
- 现价取腾讯 `qt.gtimg.cn` 实时接口；盘前/收盘后该接口返回的是最近一次成交价（即昨收/今收），属正常，非 bug。
- 重启会使内存态 `_SESSIONS` 清空，已登录用户需重新走一次 CAS 登录。
