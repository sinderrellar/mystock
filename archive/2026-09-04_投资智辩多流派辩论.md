# 投资智辩：多流派 AI 投资想法验证（前端 + 后端 + 辩论 agent）

日期：2026-09-04

## 改了什么

新增「投资智辩」交互功能，对标新浪财经「投资智辩」赛题：用户输入投资想法 → 价值/成长/趋势三流派 AI 用真实财经数据辩论 → 生成可验证投资页面 → 支持自然语言微调。技术栈由老板拍板：**前端 React SPA**，**辩论引擎用 `wecode -p` 直接执行（作为一个 agent）**。

新增文件：

| 文件 | 职责 |
|------|------|
| `skills/debate/agent.md` | 辩论编排层（首席辩论官）：三流派并行派生子代理 → fact_check → 汇总 → 页面 JSON |
| `scripts/debate_engine.py` | 唯一调 wecode 的地方：`run_agent`/`parse_json`/`clean_output`/`get_data_base`/`debate` |
| `scripts/api_server.py` | FastAPI：`/api/debate`、`/api/data/{code}`、`/api/refine`、`/api/demo`、`/api/health`、静态 serve `web/dist` |
| `web/`（React + Vite） | `App.jsx` 状态机 + `IdeaInput`/`DebateView`/`PageView`/`RefinePanel` 组件 + 深色卡片风 |
| `data/demo_debate_300750.json` | 宁德时代冒烟真实结果，供 `/api/demo` 秒开预览 |

## 为什么这样做

1. **不新造三流派 skill**：复用现有 skills 体系——价值派=stock_value_analyse、成长派=fundamentals_analyst、趋势派=technical_analyst、事实核查=fact_checker。辩论编排只需一个 `skills/debate/agent.md` 做调度。
2. **wecode 作为 agent**：老板拍板不在 FastAPI 里手写 LLM SDK，用 `wecode -p` 直接执行（Claude Code 封装，走本地代理 127.0.0.1:3456）。
3. **数据底座复用**：`PortfolioStrategy.analyze_stock(code, market)` 一次拿全 price/trend_signal/llm_context/news/moneyflow，避免重造数据层。
4. **单端口**：FastAPI 同时 serve API 和构建后的 React SPA，前端 `/api` 由 vite proxy 转发。

## 怎么验证

```bash
# 前端构建（36 模块，dist 产物 ~153KB js）
cd web && npm run build

# 后端起服务
cd /data2/liuyu20/mystock
venv/bin/python -m uvicorn scripts.api_server:app --host 0.0.0.0 --port 8000

# 验证
curl http://localhost:8000/api/health   # {"status":"ok"}
curl http://localhost:8000/api/demo     # 返回完整 idea/schools/fact_check/synthesis/page/asset
curl -o /dev/null -w "%{http_code}" http://localhost:8000/   # 200 静态页
```

浏览器打开 http://localhost:8000 → 点「查看演示」→ 秒开宁德时代完整三流派辩论（含 fact_check 抓出的「351→500 不是翻倍」数字错误）。

## 已知局限 / 待办

- **实时辩论慢**：`wecode -p` 端到端跑在 deepseek-v4-pro 模型（冒烟用 moonshot-kimi-k2.7-code-highspeed 快很多），茅台案例曾 9+ 分钟未返回（`run_agent` timeout=600s）。演示数据用预置 JSON 规避此问题。后续需优化模型路由或拆分并行流派调用。
- 未做 SSE 流式输出，实时辩论为同步等待 + 前端 loading。
- 图表组件（Chart.jsx）尚未接入真实 K 线数据。
