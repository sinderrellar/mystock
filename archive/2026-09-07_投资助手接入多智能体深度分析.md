# 投资助手接入多智能体深度分析

日期：2026-09-07

## 为什么改

「投资助手」（`/research/chat` 多轮对话）此前每一轮都是**单 agent 直接答**——`debate_session.run_debate_turn()` 拼一段裸角色 prompt（不含任何 agent.md 编排），wecode 一次调用吐 markdown，没有真正的多智能体。

而「投资智辩」（`debate_engine` + `skills/debate/agent.md`）和「深度研究」（`research_engine` + `skills/*/agent.md`）已经是**文档驱动的多智能体编排**：一次 wecode -p 调用，主代理读 agent.md，内部派生子代理（每个子代理对应 `skills/*/xxx.md` 角色文件），最后汇总。

本次需求：让投资助手在回答「某只股票 / 某个方向」时，也能用多智能体从多个角度出答案。

老板拍板的五个决策：
1. **触发方式**：聊天输入区加**下拉选项**「普通分析 / 深度分析（多智能体）」，由用户每轮选择。
2. **多角度集合**：按问题类型动态选——个股→价值/成长/趋势 + 风险；行业/方向→格局/政策/竞争/趋势；大盘→筹码/资金/情绪。全部复用现有 `skills/` 子代理，不新写角色文件。
3. **结果归档**：深度分析结论顺带归档到 `reports/`，纳入报告库复用。
4. **联网开关**：深度分析加「联网」开关——开 = 子代理可联网搜索补证并标来源；关 = 只用数据底座。独立事实核查不单独派子代理，合并到主代理汇总时顺带核查。
5. **自动识别标的**：去掉「绑定股票代码」输入框，改为自动识别标的再取数据底座——deep 模式由主代理（智能体）语义识别（简称/英文/港股都能认），normal 模式由后端正则快速识别。

## 改了什么

### 1. 新建 `skills/assistant/agent.md`（核心编排文件）

投资助手深度分析的编排：Step 0 判断问题类型 + **识别标的**（个股问题语义识别代码，含简称/英文/港股/美股）→ Step 0.5 取数据底座（个股问题用 Bash 调 helper）→ Step 1 按类型并行派子代理（读 `stock_value_analyse` / `fundamentals_analyst` / `technical_analyst` / `risk_manager` / `industry_research/researcher` / `news_analyst` / `sentiment_analyst` / `chip-analyzer` 等现有 md）→ Step 2 汇总回答（顺带核查关键数字，不单独派 fact_checker 子代理）。含「联网开关」约束：开则子代理可联网并标来源，关则只用证据底座；取数据底座走本地工程数据、不受联网开关限制。输出纯 markdown、不下单边指令、不编造数据。

### 2. 新建 `scripts/assistant_evidence.py`（取数 helper）

供主代理用 Bash 调用的取数脚本：`python3 scripts/assistant_evidence.py <code> [--market A股] [--session <sid>]`。
- 复用 `debate_session._build_evidence` 取定量数据 + 相关报告摘要，stdout 输出文本版证据底座。
- 可选 `--session`：取数后 `$set` 回写 session 的 code/market/evidence（供前端展示 + 后续轮复用）。
- 顶部 re-exec 兜底：系统 python3 缺 pymongo 时自动切到 `venv/bin/python`（主代理用任意 python 调都能跑）。

### 3. `scripts/debate_session.py`

- `create_session` 加 `mode`、`web` 参数，写入 session 文档。
- 新增 `_auto_identify(question)`：后端正则快速识别（先 `\b\d{6}\b` 到 `stock_basic_info` 验证代码，再按名称长度降序包含匹配中文名），仅 normal 模式用。
- `run_debate_turn` 从 `task.payload` 读 `mode`、`web`，分两支：
  - `normal`：原逻辑不变（单 agent 直接答，`DEBATE_TIMEOUT` 600s），`code` 为空时用 `_auto_identify` 正则识别 + 取数回写。
  - `deep`：prompt 改为「读 `skills/assistant/agent.md` 严格按它执行」，注入【会话ID】+【取数助手】命令；**不预识别**，标的识别交给主代理（智能体语义识别）+ Bash 调 helper 取数（helper 回写 session）；超时用 `ASSISTANT_DEEP_TIMEOUT`（1200s）。
  - deep 模式拿到 reply 后，用 `research_engine.archive_filename("assistant_deep", ...)` 定名 + `_write_report` 落盘 `reports/`（只增不改，归档失败不阻断回复）。
- assistant 消息写 `meta={"mode": mode}`，供前端标注「深度分析」标签。

### 4. `scripts/research_engine.py`（新增归档类型 + 修复检索缺陷）

- `VALIDITY_DAYS["assistant_deep"] = 14`、`TYPE_LABEL["assistant_deep"] = "助手深度分析"`。
- `classify_type` 加识别分支（`assistant_deep|助手深度`，放在 chip 之后、估值之前）。
- `archive_filename` 加分支：`assistant_deep_{target or code or name}_{date}.md`。
- `extract_target` 的类型前缀正则加 `assistant_deep`，让报告 target 提取干净。
- **修复 `find_reports_for_target` 缺陷**：原 `if r["fresh"]: score += 3` 让「新鲜但无关」的报告无条件进入候选，导致无相关报告时兜底塞入最新鲜的无关报告（实测宁德时代查到了中国移动的报告）。改为先判相关性（code/name/industry/chip 命中），`score==0` 直接跳过，`fresh` 仅作排序加分。

### 5. `scripts/api_server.py`

`DebateSessionCreate` / `DebateMessageCreate` 加 `mode`、`web` 字段，端点透传到 `create_session` / `enqueue` 的 `payload`。

### 6. 前端

- `web/src/api.js`：`sendDebateMessage` 加 `mode`、`web` 参数。
- `web/src/pages/ResearchPage.jsx` `ChatPanel`：
  - 加 `mode`（默认 `normal`）、`web`（默认 `true`）state + 输入区加 `<select>` 下拉（普通分析 / 深度分析，busy 时禁用）+ 深度分析时显示「联网」checkbox。
  - `send()` 把 `mode`、`web` 传给 `createDebateSession` / `sendDebateMessage`（不再传 `code`）。
  - **移除「绑定股票代码」输入框**（含 `codeInput` state 及 newTopic/send 里的 set 调用），改为后端自动识别；话题列表空标的文案由「未绑定标的」改为「通用话题」，空状态提示改为「自动识别问题里的股票/行业」。
  - 等待文案按 mode 区分（深度分析「约 5-10 分钟」）。
  - assistant 气泡按 `m.meta?.mode === 'deep'` 标注「🧠 深度分析」标签。

## 怎么验证

1. `python3 -m py_compile` 三个后端文件语法通过。
2. `classify_type` / `archive_filename` 单元验证：`assistant_deep_宁德时代_2026-09-07` → type=assistant_deep、target=宁德时代、归档名正确。
3. **DRY RUN 端到端**（`RESEARCH_DRY_RUN=1` + 隔离 `RESEARCH_REPORTS_DIR`，用 venv python）：
   - deep 会话 mode=deep、assistant 消息 `meta={'mode':'deep'}`、`assistant_deep_*.md` 落盘成功。
   - normal 会话 mode=normal、不落盘（回归无影响）。
   - web 字段全链路：`web=False` / `web=True`（默认）均正确存储并注入 prompt。
4. **标的识别**：
   - normal 正则识别 `_auto_identify` 单测 6 例全对（宁德时代→300750、代码优先、行业/大盘不误识别）；端到端 `session.code` 自动回写 `300750`、`evidence.data` 四维齐全。
   - deep 主代理识别：DRY RUN 下 `session.code` 保持空（不预识别、交给主代理），prompt 含【会话ID】+【取数助手】命令。
5. **取数 helper**：`assistant_evidence.py 600941` 正确输出中国移动数据底座；系统 `/bin/python3`（缺 pymongo）调用时自动 re-exec 到 venv python。
6. **报告检索修复**：`find_reports_for_target(code=300750, name=宁德时代)` 修复后不再返回中国移动报告（仅 chip_analysis）；`code=600941, name=中国移动` 正确命中自己的 investment_research 报告。
7. 报告库识别 + 复用命中：`list_reports` 正确标「助手深度分析」且 fresh；`find_fresh_report` 命中归档。
8. 前端 `npm run build` 成功（312 模块，2.56s）。

## 局限 / 待办

- 未做真实 wecode 多智能体派发的端到端验证（DRY RUN 只验证链路，未真跑子代理）。首次真实深度分析建议观察 wecode 会话是否按预期：Step 0 识别标的 → Bash 调 helper 取数 → 派生 value/growth/trend/risk 子代理；5-10 分钟超时是否够。
- **主代理识别标的的依赖**：deep 模式标的识别依赖主代理（LLM）执行 Step 0/0.5，LLM 可能识别错代码或漏调 helper；识别不准时无数据底座，联网开靠搜索兜底、联网关则明说「无数据底座」。normal 模式仍用正则快速识别（只认 6 位代码+中文全名，不认简称/英文/港股）。
- 深度分析归档统一用 `assistant_deep` 类型（14 天有效期），未区分个股/行业子类型；报告库检索靠 target 归一化匹配，命中正常。
- `assistant_deep` 有效期 14 天为初值，若观察到期内观点过时，可调短。
- `find_reports_for_target` 修复后，无相关报告时仅返回 chip_analysis（若新鲜）或空，不再兜底无关报告——这会让证据底座「更干净但也更空」，属预期行为。
