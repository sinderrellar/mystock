# 大盘宽度/资金面：两融+行业资金流修复，前端补渲染实际数据

日期：2026-09-08

## 为什么改

老板反馈「大盘宽度 / 资金面」面板两点：

1. **「已就绪 ✓」是啥意思、为啥不展示数据** —— 前端 `BreadthCard` 只渲染状态徽章（`available ? '已就绪 ✓' : '暂不可用'`），从不渲染后端返回的实际数值。后端 5 项里 3 项（大盘宽度/组合相关性/主力资金）本就 `available=true` 且带完整数据，但前端一个数字都不显示。
2. **两融余额、行业资金流「暂不可用」能不能弄出来** —— 排查后两个都是可修的 bug，数据其实都在。

## 根因

### 两融余额 `_get_margin_data()`
- 只查 `pro.margin(trade_date=today)`，但**两融数据 T+1 发布**，当日常空 → 恒 `available=false`。
- 且 Tushare `margin` 按交易所返回多行（SSE/SZSE/BSE），原代码 `df.iloc[0]` 只取第一行（北交所，融资余额仅 84 亿），漏掉沪深两市。

### 行业资金流 `_get_industry_moneyflow()`
- 按 `computed_at` 字段过滤，但 `stock_signals` 里资金流数据的日期字段是 **`moneyflow_date`**（`computed_at` 不存在，恒空）。
- 实测 `stock_signals` 有 1149 只 `moneyflow_net` 非 0、`moneyflow_date=20260907`，数据齐全，纯字段名写错。

## 改了什么

### `scripts/market_data_provider.py`

1. `_get_margin_data()`：
   - 从今天往前回退最多 5 个自然日，取最近有数据的那天（覆盖 T+1）；
   - **跨交易所求和**（不再 `iloc[0]`），金额元→亿元，新增 `rzrqye`（两融余额合计）。
2. `_get_industry_moneyflow()`：
   - 过滤字段 `computed_at` → `moneyflow_date`（`%Y-%m-%d` → `%Y%m%d`）；
   - `data_date` 取 `moneyflow_date`；docstring 修正为「缓存到 stock_signals」。

### `web/src/pages/PortfolioPage.jsx` — `BreadthCard`

- 删除「已就绪 ✓」占位徽章，改为**按行渲染实际数据**：
  - 大盘宽度：宽度等级 + 站上 MA20/MA60 占比 + 样本数；
  - 组合相关性：平均相关 + 高相关对（前 3 对）；
  - 两融余额：两融合计 + 融资/融券 + 日期；
  - 全市场主力资金：主力流入/流出（带涨跌色）+ 近 5 日净流入天数 + 截至日期；
  - 行业资金流：流入/流出前 3 行业及金额；
  - 不可用仍显示 `暂不可用` + 原因。

## 怎么验证

`py_compile` 通过；直接跑后端函数（2026-09-08 盘中）：

- 两融余额：`available=True`，融资 26207.42 亿 / 融券 287.37 亿 / 两融合计 26494.79 亿，date 20260907（T+1 回退正确）。
- 行业资金流：`available=True`，1149 只汇总，流入前三 通信设备/元器件/半导体，流出前三 银行/电气设备/证券。
- 大盘宽度：`available=True`，站上 MA20 64.8% / MA60 35.2%，宽度「正常」，样本 3970 只。
- `npm run build` 成功；重启 api_server（PID 21113）部署后端改动。

## 局限 / 待办

- 两融日期仍用 `_utc_now()`（UTC）而非北京时间，凌晨 0–8 点存在跨日偏差；因已回退 5 天，实际总取到最近交易日，影响可忽略，但可后续统一换北京时间口径。
- 两融余额现在是「全市场（沪深北）合计」，更贴近直觉；若老板要按交易所分列，需再加维度。
