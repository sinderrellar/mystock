# 2026-09-04 深度研究模块：研究报告库 + 后台研究任务 + 综合研判 + 投资助手

## 改了什么

把 CLAUDE.md 分析编排里「阶段3 定性深化 + 阶段4 综合研判」从「Claude Code 手动跑」落地成「控制台可点、可看、可回溯」，并把 4 个研究类 skill 的报告结论 + 定量数据统一作为「投资助手」的证据底座。入口只有一个：「研究」分组下的 **研究库**（📚）+ **投资助手**（💬）。

### 后端（scripts/）

**1. `research_engine.py`（新，纯引擎，无 FastAPI/Mongo）**
- 报告库：`list_reports()/read_report()` 扫 `reports/`，`parse_report_filename()` 解析文件名 → `{type,target,date}`，套 CLAUDE.md 有效期规则（investment_research 14 天 / industry_research 14 天 / stock_value_analyse 30 天 / chip_analysis 7 天）算 `fresh/expired`。
- 研究检索：`find_fresh_report()`（命中新鲜报告跳过重复研究）、`find_reports_for_target()`（给投资助手检索证据底座，代码命中>名称命中>行业命中打分）。
- 归档名映射 `archive_filename()`：新报告统一命名（`investment_research_{name}_{date}.md` 等），与历史命名一致。
- `run_research()`：组 prompt（指向 `skills/*/agent.md`）→ `debate_engine.run_agent` → 落盘 `reports/`（stdout 兜底写入，<100 字符判失败）。
- `run_verdict()`：`PortfolioStrategy().review()` 组合全景 + 新鲜报告 → 喂 wecode 产三层研判（事实/推断/建议）；失败走 `_verdict_fallback` 规则兜底（明确标注「规则生成」）。
- CLI（定期入口）：`python3 scripts/research_engine.py --type chip_analysis`（也支持 investment_research/industry_research/stock_value_analyse/verdict），失败 exit 1。

**2. `research_tasks.py`（新，任务持久化 + 队列 + worker）**
- `sim_research_tasks`（per-user，status = queued|running|done|failed|interrupted）。
- 单 worker 线程 + `queue.Queue`（FIFO，同时最多 1 个 wecode），POST 只入队立即返回。
- `_execute_task()` 按 type 分发：verdict→`run_verdict`，debate_turn→`debate_session.run_debate_turn`，其余→`run_research`。
- `recover_interrupted_tasks()`：重启把遗留 queued/running 置 interrupted（update 非 delete），只恢复 `created_at < 进程启动时间` 的任务（避免误伤刚入队的）。

**3. `debate_session.py`（新，投资助手多轮会话）**
- `sim_debate_sessions`（per-user，内嵌 `messages[]`，软删 `active=false`）。
- `create_session/list_sessions/get_session/add_message`（`$push` 追加）。
- `_build_evidence()`：绑定标的时检索相关新鲜报告（含摘要）+ `get_data_base()` 定量数据，缓存进 session。
- `run_debate_turn()`：worker 执行单轮 —— 拼 prompt（话题 + 证据 + 最近 6 条历史 + 本轮问题）→ wecode → 追加 assistant markdown 回复。

**4. `api_server.py`（改）**
- 新增：`GET /api/research/reports`、`GET /api/research/reports/{name}`、`POST /api/research/tasks`、`GET /api/research/tasks`、`GET /api/research/tasks/{id}`。
- 新增：`POST /api/debate/sessions`、`GET /api/debate/sessions`、`GET /api/debate/sessions/{id}`、`POST /api/debate/sessions/{id}/messages`。
- `research_task_create` 允许 `type="verdict"`（无有效期去重，每次手动触发），verdict 入队带 `payload.user_id` 供 `sync_to_yaml` 后再 review。
- 旧 `/api/debate`、`/api/data/{code}`、`/api/refine`、`/api/demo` 保留不动。

## 为什么

- 系统里 4 个研究类 skill 只能靠 Claude Code 手动触发，产出的 20+ 份报告控制台看不到；现在统一落到「研究库」可看、可回溯。
- 研究/辩论都依赖 wecode（同步阻塞 2-9 分钟），前端不能同步等 → 统一走「后台队列 + 前端轮询」，POST 立即返回。
- 研究结论 + 定量数据一起作为「投资助手」证据底座，辩论不再只靠实时定量数据，研究报告反哺对话。
- 「综合研判」= 组合全景 + 新鲜报告 → 三层研判，串起阶段2→阶段4。

## 局限

1. **wecode 慢/超时**：`RESEARCH_TIMEOUT` 默认 1200s（stock_value_analyse 子代理多），辩论轮 `DEBATE_TIMEOUT` 默认 600s，env 可调；超时→任务 failed 带 error。
2. **并发**：单 worker = 单 wecode，多任务排队 `queued`；`uvicorn --workers N` 下进程内队列不跨进程（v1 不处理）。
3. **报告解析不完美**：旧报告命名不统一，best-effort 归 `other` 不崩溃；新归档名保证精确命中。
4. **综合研判/投资助手的 LLM 质量**：依赖 wecode 输出，研判失败走规则兜底（仅列事实层），回复失败标注「空回复」。
5. **对话中触发研究任务**：老板方向「用户交互时再看如何发起研究」，当前投资助手只做「证据底座 + 多轮回答」，尚未在对话内一键发起后台研究（需后续在 ChatPanel 加「触发研究」按钮 → 复用 `createResearchTask`）。
6. **Mongo 不可用**：任务/会话端点 503（同 sim_trade），报告列表/读取仍可用（纯文件）。

## 补丁（同日，老板验收反馈两处）

老板验收反馈两个问题，逐一修复：

1. **「投资助手点击发送没反应」**：排查 Mongo 发现会话实际已产生完整 assistant 回复（`liuyu20` 的「中国移动怎么样？」2 条消息 user+assistant），后端链路 200 OK。根因是前端「正在组织回复…」气泡只绑 `busy`（发送瞬间 ~200ms 就置 false），wecode 后台跑 1-3 分钟期间无任何“进行中”指示，用户感觉“点了没反应”。**修复**：气泡条件改 `(busy || pollTaskId)`，轮询期间持续显示。数据也确认老板控制台 user_id 是 `liuyu20`（CAS 身份），非 `zhongyue3`（后者是冒烟/测试用户）。

2. **「研究库发起研究后没有任务列表」**：触发研究只弹一行“任务已入队”内联提示，无任务列表。**修复**：`ResearchPage.jsx` 新增 `TaskList` 组件（类型标签 + 状态徽标 排队中/运行中/已完成/失败/已中断 + 目标 + 完成报告/失败原因），`LibraryPanel` 挂载即拉 `GET /api/research/tasks`、有 queued/running 时每 3s 轮询，`TriggerBar` 入队后立即刷新任务列表。`styles.css` 加 `.task-list/.task-item`。
