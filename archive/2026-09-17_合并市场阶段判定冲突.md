# 合并市场阶段判定与阈值套件两套方案（merge 冲突解决）

日期：2026-09-17
提交：91bffc1

## 背景

`main` 与 `origin/main` 各自分叉 2 个提交后合并，4 个文件冲突：

- 本地方向（`c4f720a`）：市场宽度 → 阈值套件 + 防抖（`_resolve_regime`）+ 前端漏斗全量输出
- 远端方向（`48f881d`）：市场阶段判定模块（`market_phase.py`，4 信号聚合）+ 熊市熔断

两套方案都往"市场状态驱动 buy_plan"走，路线不同，形成设计分歧。经老板拍板走**融合**路线。

## 改了什么

### 1. `scripts/buy_plan.py`（融合）
- 保留 `_resolve_regime`（防抖 + 档位阈值套件 + 弱市 ROE 门槛）为主干
- 叠加 `_get_market_phase`（`market_phase.py`）作**顶层熊市熔断**：先判 market_phase，`decline`（`allow_new_buy=False`）直接 return，不跑初筛
- `dip_only` 低吸约束 + `quality<60` 质量门槛并入 `passed` 过滤层（`pool` 仍全量供前端漏斗）
- report 同时输出 `thresholds`（你的）+ `phase`（对方的）
- 两条"强/弱"线不一致（regime 60/35 于 config，market_phase 55/35 硬编码）已加注释说明：职责不同、勿强行统一

### 2. `scripts/market_data_provider.py`（你的为主体 + 补关键字段）
- 过期判定/实时价注入采用 `historical_mode`/`live_mode`（防 look-ahead，比对方严谨）
- `_get_margin_data` 保留"回退最近交易日 + 跨交易所求和"，**补上 `rzye_change` 环比字段**（`market_phase` 两融趋势信号依赖，缺失会降级为 3 信号）

### 3. `scripts/precompute_history.py`（你的为主体 + 保留对方防 look-ahead）
- PE/PB 反算采用 `_find_financial_as_of`（修复 `estimated_disclosure` 缺失致 1893 只 akshare 标的因子塌缩为 0）
- 保留对方 forecast 一致预期的"仅今天可用"门控（防 look-ahead）
- `fin` 用于 PE/PB 反算，`factor_fin`（剔除 forecast）用于因子计算，`override_momentum` 传 V2 动量

### 4. `.gitignore`（合并）
你的规则为准 + 保留对方 `*/__pycache__`

## 为什么

两套方案互补而非互斥：`_resolve_regime` 解决"用哪套阈值/权重"的精细化择时，`market_phase` 解决"能不能买"的宏观熊市熔断。融合后两边价值都保留，`market_phase.py` 模块不沦为死代码。

## 怎么验证

1. `python3 -m py_compile` 四个文件语法编译通过
2. 关键引用完整性检查：`_find_financial_as_of`、`_is_dip_candidate`、`calculate_composite_score` 的 override 参数、`market_phase.py` 的 `determine_market_phase`/`extract_phase_inputs` 均存在且签名匹配
3. `git diff --cached --check` 无 whitespace 问题
4. 重启 api_server（uvicorn :8000），健康检查 `{"status":"ok"}` 通过

## 局限（未覆盖）

- 未跑 `buy_plan.run()` 完整运行测试（需 MongoDB + 实时行情，有副作用且慢）
