# 投资助手：并发化 + 换标的识别 + 全表扫描优化

日期：2026-09-07

## 背景

前端「投资助手」（多轮对话，复用 `/api/debate/sessions/*`）后端链路为：
`research_tasks`（单 worker 队列）→ `debate_session.run_debate_turn`（单轮执行）→ `debate_engine.run_agent`（subprocess 调 wecode）。

排查发现 3 个问题：研究任务串行阻塞、会话绑定标的后换标的失效、标的识别全表扫描。

## 改动

### 1. 研究任务队列并发化（问题1）

**scripts/research_tasks.py**
- 单 worker 线程 + `queue.Queue`（同时最多 1 个 wecode）→ `ThreadPoolExecutor` 有界线程池。
- 并发度由环境变量 `RESEARCH_WORKERS` 控制，默认 3。
- `recover_interrupted_tasks()` 移到线程池惰性启动时执行一次（保持重启恢复语义）。

**scripts/debate_engine.py**
- `run_agent_with_session` 从「目录 diff 猜新 session 文件」改为 `--session-id <uuid>` 精确绑定。
- 新增可选参数 `session_id`（缺省自动生成 `uuid4`），session 文件路径确定为 `<session_id>.jsonl`。
- 删除了只服务于旧 diff 逻辑的 `_snapshot_session_files()`（及 `glob` 依赖）。

**为什么**：单 worker 串行下，一次 deep 分析 5-10 分钟会阻塞所有后续研究/对话轮；而旧 session 捕获靠目录 diff，并发下多个 wecode 会互相抢错会话文件。`--session-id` 让 session 追溯并发安全。

### 2. normal 模式换标的识别（问题3）

**scripts/debate_session.py** `run_debate_turn`
- 条件从 `if mode != "deep" and not code:` 改为 `if mode != "deep":`，且 `if auto_code and auto_code != code:`。
- 即：normal 模式每轮都重新 `_auto_identify`，识别到新 code 且不同于当前绑定的 code 时，重建 evidence 并回写 session。

**为什么**：原逻辑只在 code 为空（首轮）时识别，会话一旦绑定某只股票，后续轮换问另一只股票不会切换标的，导致证据底座错配。

### 3. `_auto_identify` 全表扫描优化（问题4）

**scripts/debate_session.py**
- 新增 `_name_code_map(basic)`：name→code 映射进程级缓存（TTL 1h）。
- `_auto_identify` 的名称包含匹配改从缓存读取，不再每轮 `basic.find({})` 全表拉 5555 条。

**为什么**：stock_basic_info 低频更新（每周日才 import-universe-light），全表拉取 + Python 过滤每轮重复做，无必要。

## 验证

- 语法：`py_compile` 三文件通过。
- 问题4：`_auto_identify` 识别「宁德时代」→300750、「比亚迪」→002594；「半导体行业」「继续分析」正确返回空（不误判）。缓存首载 5555 条，命中耗时 0.000001s。
- 问题3：同一会话先问宁德时代（code 回写 300750）再问比亚迪（code 回写 002594），换标生效。
- 问题1：3 个慢任务（各 sleep 2s）并发完成耗时 2.4s（串行应 ~6s），证明线程池并发生效；任务状态正确流转 queued→running→done。
