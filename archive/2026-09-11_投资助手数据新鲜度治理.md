# 投资助手数据新鲜度治理

## 改了什么

1. `scripts/debate_session.py`
   - `_build_evidence()` 返回值新增 `built_at`（ISO 时间戳），记录底座构建时刻。
   - 新增 `_evidence_is_stale(evidence)`：跨自然日 / 超过 TTL / 缺 `built_at` 均判过期。
   - 新增常量 `EVIDENCE_TTL_SECONDS`（默认 1800s，env `EVIDENCE_TTL_SECONDS` 可调）。
   - `_evidence_text()` 置顶输出「【数据截至】…」，明确告知 LLM 数字取自何时、不得当实时值。
   - `run_debate_turn()`：统一 normal/deep 两档——每轮后端先 `_auto_identify` 识别标的；
     换标的 / 底座过期时重建并 `$set` 回写 session（只改不删）。deep 模式改为后端预取，
     不再赌主代理是否跑 `assistant_evidence.py`（helper 保留作兜底）。
2. `web/src/pages/ResearchPage.jsx`：话题标题栏「证据」后追加「· 截至 MM-DD HH:MM」。
3. `skills/assistant/agent.md`：Step 0.5 说明后端已预取新鲜底座，多数情况无需再取数。

## 为什么改

证据底座原先只在会话创建时构建一次并缓存进 `session.evidence`，之后同一标的的
多轮追问、隔天再问，仍沿用首轮的现价/RSI/估值。这构成 CLAUDE.md 明令禁止的
「静默降级」——用过期数据看似完成了回答。deep 模式此前完全靠主代理自觉跑
`assistant_evidence.py` 回写，不确定。本次让底座按「跨日 / TTL」自动过期重建，
并把构建时间显式暴露给 LLM 与前端。

## 怎么验证

- `venv/bin/python -m py_compile scripts/debate_session.py` 通过。
- `_evidence_is_stale` 6 用例全过（空/非法/1 分钟内/超 TTL/跨日）。
- `_evidence_text` 确认「数据截至」置顶且在「数据自检」之前。
- 边界走查：新会话首次问股票→重建；同标的 30min 内追问→复用；30min 后/隔天→重建；
  换标的→重建；无标的泛问→跳过；deep 模式→后端预取。

## 局限 / 后续

- TTL 默认 30 分钟是折中：`_build_evidence` 会走行情多级 fallback + `analyze_stock`，
  重建有秒级成本，过短会加重。可按 env 调整。
- 底座失败（`data._error`）时 TTL 内不重试，避免每轮重打失败数据源；跨日会重试。
- 尚未做「流式输出」与「deep 降本提速 / 子代理可追溯」，属后续优化批次。
