# 龙虎榜导入时序修复

日期：2026-09-08

## 改了什么

1. **`scripts/data_import_pipeline.py` → `import_top_list()`**：回溯逻辑从「最近 5 个**自然日**」改为「最近 5 个**交易日**（跳过周末）」。

   ```python
   # 旧
   for i in range(5):
       dt = (datetime.now() - timedelta(days=i)).strftime("%Y%m%d")

   # 新
   trade_dates: List[str] = []
   cursor = datetime.now()
   while len(trade_dates) < 5:
       if cursor.weekday() < 5:  # 周一~周五计为交易日
           trade_dates.append(cursor.strftime("%Y%m%d"))
       cursor -= timedelta(days=1)
   for dt in trade_dates:
   ```

2. **系统 crontab**：龙虎榜触发时间 `17:00` → `20:30`。

3. **`config/crontab_stock.txt`**：同步为实际 crontab 的最新状态（全路径 + 龙虎榜 20:30 + precompute 21:00），顺带修掉了模板里残留的 `venv/bin/python` 相对路径隐患。

## 为什么改

- 龙虎榜是交易所**盘后发布**（约 18:00–21:00），原 17:00 跑 `import-top-list` 时当天数据还没出，导致当天龙虎榜永远 T+1 才入库。本次 9-07 的缺口就是这么产生的。
- 原「5 个自然日」回溯在跨周末时只有 3 个交易日有效，节假日更少，极端情况下漏补。

## 怎么验证

- 新逻辑回溯验证：9-08 周二 → 正确输出 `[0908, 0907, 0904, 0903, 0902]`，跳过 0905/0906 周末。
- 实际跑 `import-top-list`：成功，`top_list` 日期分布变为 `0902(71)/0903(53)/0904(55)/0907(66)`，其中 9-02 是旧逻辑漏掉、本次补上的交易日。
- `crontab -l` 确认龙虎榜已改为 `30 20 * * 1-5`。

## 影响范围

- 仅龙虎榜导入链路，其余数据不动。
- 20:30 与 20:00 的一致预期任务有约半小时重叠，但龙虎榜任务本身几秒完成、数据量小，无冲突。
