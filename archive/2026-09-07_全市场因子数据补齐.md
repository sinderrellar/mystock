# 全市场因子数据补齐：日线缺口 + get_bars 历史模式修复

日期：2026-09-07

## 背景

老板要求「继续。。把数据都补齐」。上一轮排查已确认因子数据管道是坏的：`stock_factors`/`stock_trends`/`stock_meta` 只有 293 条（应为 ~5200），导致 buy_plan 的 `③ 因子: 200 → 0 只`，`recommendations=0`。

本轮继续深挖，定位到**根因是 `stock_daily_quotes` 缺了 3262 只股票的日线**——只有 2293 只有日线，其余 3262 只来自 `universe_light_sina` 轻量导入（只写 code/name/close/latest_amount/industry，无日线、无财务）。precompute_history 的输入源是 daily_quotes，没日线就算不出 trend/factor。

## 根因链（完整）

```
全市场 5555 → 只有 2293 只有日线（轻量导入 3262 只缺日线）
  → 缺日线 → precompute 算不出 trend/factor
  → buy_plan 按成交额 top200 的池：176 只是 301xxx（创业板注册制新股），仅 6 只有日线
  → 因子池 ∩ top200 = 0 → ③ 因子 200→0 → recommendations=0
```

之前误判过一次「daily_quotes 为空」——是查错了集合名（实际名是 `stock_daily_quotes`，有 455,673 条 / 2293 只），正确结论是「daily_quotes 完整但只覆盖 2293 只」。

## 改了什么

### 一、`scripts/market_data_provider.py`：`get_bars` 历史模式修复

**问题**：`get_bars` 里 MongoDB 数据只要 `age > 1` 天就判 `stale`，接着走 Yahoo 逐只网络补齐。precompute 用 `as_of_date=2026-09-04`（历史日期）时，数据相对"今天"（09-07，周一）3 天旧，被误判 stale，触发每只股票一次 Yahoo 网络请求——这就是 precompute 慢的第二个瓶颈（第一个是上一轮已修的 `get_trend_signal` 实时价注入）。

**修复**：加 `historical_mode` 判断——`as_of_date` 给定且在过去时，MongoDB 里 `<= as_of_date` 的数据就是该日期的正确快照，直接返回，不因相对今天过期走 Yahoo。既避免 look-ahead bias，又让 precompute 免掉逐只网络请求。

```python
today_str = datetime.now().strftime("%Y-%m-%d")
historical_mode = bool(as_of_date) and as_of_date < today_str
...
if not result["stale"] or historical_mode:
    return result
```

### 二、`scripts/backfill_daily_quotes.py`（新增）：补全缺失日线

用**同花顺 K 线** `d.10jqka.com.cn/v6/line/hs_<code>/01/last360.js` 逐只补齐 360 个交易日日线，写入 `stock_daily_quotes`。

**为什么用同花顺**（对比测试）：
| 数据源 | 结果 |
|--------|------|
| 腾讯 fqkline | ❌ 连续 ~600 次请求后 501 限流，数小时未恢复 |
| 东财 push2his | ⚠️ 间歇 RemoteDisconnected（3 次里 2 次掉线） |
| **同花顺 d.10jqka** | ✅ 稳定，单前缀 `hs_` 覆盖沪深、不分市场，`last360` 一次 360 根前复权日线含成交额，只到最近完整交易日 |

字段顺序 `date,open,high,low,close,volume,amount`（注意与东财 open/close/high/low 顺序不同，已按同花顺口径解析）。6 线程并发，`--workers` 可调。

**约束遵守**：只 upsert（`ReplaceOne` + `$setOnInsert created_at`），禁 delete；幂等（跳过已有日线的股票）；范围限定 6/0/3 开头的 A 股（北交所 920/8/4 不在 precompute 范围，属后续增强）。

## 已知边界（如实告知老板）

- 9 只股票补日线失败（300119/300664/603066/603159/603637/605077/605255/688779 等，疑似退市/停牌/新三板转板），影响可忽略。
- 北交所 920/8/4（341 只）仍未补日线：precompute 只算 6/0/3 开头，补了也用不上，属后续增强。
- 财务数据 `stock_financial_data` 仍是 2293 只的旧数据，3262 只轻量股票缺财务（EPS/BPS），导致其 factor 的 value/quality 维度无 PE/PB 输入（pe/pb=None，factor 用默认值兜底）。不影响 buy_plan 出结果（momentum/cycle/turnaround 依赖价量+行业，不依赖财务），但会拉低这些股票的价值/质量因子精度——要补需单独跑财务导入。
- 「趋势缓存 3 天未更新」警告是**误报**：`cache_age` 用日历日算，09-04(周五)→09-07(周一) 跨周末算 3 天，但 09-04 就是最近完整交易日。周中运行时该警告会自然消失。
