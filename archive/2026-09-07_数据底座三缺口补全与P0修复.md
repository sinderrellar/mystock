# 数据底座三缺口补全 + 投资助手 P0-1/P0-2 修复

日期：2026-09-07

## 背景

上一轮已把 `get_data_base` 从 4 字段扩到 9 字段（持仓上下文/资金面/新闻/行业周期/数据自检）。
本轮老板追加三个数据缺口 + 两个遗留 P0：

- **market_breadth 恒空**（`_get_market_breadth` 取错集合）
- **pe_percentile_self 恒 null**（`_get_pe_percentile` 死代码，stock_signals 从未写入该字段）
- **港股 quote_snapshot 全失败**（yahoo 403 / akshare HK spot 连接被断 / Mongo 无港股 basic）
- **P0-1**：deep 归档用过期变量 → 报告名=问题文本
- **P0-2**：chat 轮次用 `run_agent`（无 `--session-id`）→ 无研究过程可视化

## 根因与改动

### 1. market_breadth 取错集合（`scripts/portfolio_strategy.py`）

`_get_market_breadth` 查 `stock_signals` 的 `computed_at`/`trend.status`，但 `stock_signals` 只存资金流
（`moneyflow_net`）+ 一致预期（`forecast_min/max`），从未写趋势状态；趋势状态在 `stock_trends`
（`precompute_history` 预计算，字段 `trade_date` + `status`）。

**改动**：数据源 `stock_signals` → `stock_trends`，过滤字段 `computed_at` → `trade_date`，读 `status`
（平铺，非 `trend.status`）。顺带修一个隐藏 bug：原代码用未定义的 `_utc_now()`（portfolio_strategy
只 import 了 `datetime`，无 `_utc_now`），一直抛 NameError 被 except 吞成「计算失败」。

**验证**：`market_breadth` 从 `{available:False}` → `{available:True, above_ma20_pct:64.8, above_ma60_pct:35.2, width:'正常', sample:3970}`。

### 2. pe_percentile_self 补全（`scripts/data_import_pipeline.py` + `scripts/portfolio_strategy.py`）

`_get_pe_percentile(pro, code)`（Tushare daily_basic 算 PE_TTM 历史分位）是死代码，无调用方；
`analyze_stock` 只读 `stock_signals.pe_percentile`，而该字段无人写。

**改动**：新增 `get_or_compute_pe_percentile(store, code, market)`：
- 仅 A 股（港股/美股无 Tushare daily_basic → 返回 None）；
- cache-first：先读 `stock_signals.pe_percentile`，命中即返；缺失才打一次 daily_basic，算完回写缓存。
`analyze_stock` 改调该函数（替换原来的裸 `find_one`）。

**验证**：603986 → 0.6（现算并回写 stock_signals），300750 → 22.6，00700(港股) → None。

### 3. 港股 quote_snapshot 补全（`scripts/market_data_provider.py`）

`get_quote_snapshot` 对港股四路全断：Mongo `get_basic(00700)`=False（无港股 basic）、
akshare `stock_hk_spot_em` 连接被断、yahoo v7 403 Forbidden。但腾讯行情 `qt.gtimg.cn/q=hk00700`
可用且字段齐全。

**改动**：新增 `_quote_from_tencent_hk(code)`，解析腾讯港股行情字段（实测 hk00700 校验，对齐腾讯
控股基本面）：
- `[3]` 现价、`[39]` 市盈率TTM、`[44]` 总市值(亿 HKD)、`[48]` 52周高、`[49]` 52周低、`[75]` 货币。
只映射已校验字段，PB/股息率索引未确认不臆造（避免静默错数据）。
在 `get_quote_snapshot` 的 MongoDB 分支后插入港股腾讯兜底（避免先踩不稳的 akshare/yahoo）。

**验证**：`get_quote_snapshot('00700','港股')` → `{available:true, source:'tencent', trailing_pe:16.01,
market_cap:3.99e12(HKD), 52周高677.7/低411.0, currency:HKD}`；A股 603986 仍走 mongodb 不受影响。
连带修复港股持仓上下文 PnL：liuyu20/00700 → 现价437.8、浮亏-25200(-10.32%)、距止损8.63%。

### 4. P0-1：deep 归档取过期变量（`scripts/debate_session.py`）

`run_debate_turn` 的 deep 归档用本地 `name`/`code`（在 `run_agent` 前捕获），但 deep 子代理已通过
`assistant_evidence.py --session` 回写最新 code/name，本地变量是旧的 → 报告名退化成问题文本。

**改动**：归档前 `get_session(session_id)` 重读最新 `code`/`name`（`evidence.data.asset.name`），
再拼归档名。

### 5. P0-2：研究过程可视化（`scripts/debate_session.py` + `scripts/research_tasks.py`）

`run_debate_turn` 用 `run_agent`（无 `--session-id`），wecode 会话不落盘 → `research_process` 拉不到。

**改动**：
- `run_debate_turn(task, on_session=None)` 改调 `run_agent_with_session`，wecode session_id 写入
  assistant 消息 `meta.session_id`，并作为返回值 `session_id` 返回。
- `research_tasks._execute_task` 把 `_on_session` 传给 `run_debate_turn`，使 worker 在 running 期间
  就把 wecode session_id 落库 task（前端可实时拉「研究过程」，同研究报告路径）。

**验证**：dry-run 返回 keys 正确、meta 写入 `{mode, session_id}`、on_session 不误触发；
py_compile 全通过。

## 局限 / 待办

- **港股 PB/股息率仍缺**：腾讯港股字段里 PB/股息率索引未确认，未臆造；如需可再核对腾讯字段表补上。
- **港股 pe_percentile_self 仍 None**：无 Tushare daily_basic 源；如需可考虑用腾讯/雅虎历史 PE 近似
  （但 yahoo 403，腾讯历史 PE 接口未验证）。
- **pe_percentile 未做全市场批量**：目前是 on-demand + 缓存（首查打一次 daily_basic），sector_radar
  的全市场 pe_percentile 若需要，可仿 `import_dividend_yield` 加批量 `import_pe_percentile`。
- **前端接线**：P0-2 后端已把 wecode session_id 放进 message.meta + task.session_id，前端需调
  `/api/research/process/{sid}` 渲染（本次只做后端，未动 web/）。
- **测试污染**：dry-run 验证时在 zhongyue3 的测试会话 `a608ca05`（半导体→中芯国际）上触发了一次
  换标识别（code 绑定 688981，实为正确识别）+ 追加一条 dry-run 桩消息；该会话此前已有 dry-run 桩数据，
  遵守禁删未清理。
