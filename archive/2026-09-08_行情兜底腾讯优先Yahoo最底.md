# 行情兜底改为腾讯优先、Yahoo 最底

日期：2026-09-08

## 为什么改

老板要求「改腾讯兜底，yahoo 最底」。原 `get_bars` 的远端兜底顺序是 MongoDB → Yahoo Finance，但本机环境访问 Yahoo（query1.finance.yahoo.com）会 403 白等，导致组合全景里非 A 股标的（港股/ETF）拉行情时每只多等 ~0.78s。腾讯接口（web.ifzq.gtimg.cn）在本机可用、覆盖 A 股/港股/ETF，~0.1s/次，应优先。

## 改了什么

`scripts/market_data_provider.py` 的 `get_bars`（K 线主取数入口）：

- 远端兜底顺序调整为 **MongoDB → 腾讯 → Yahoo**：MongoDB 无数据或过期时，先走 `_get_tencent_bars`（`_tencent_symbol` 映射 `hk{code}` / `sh{code}` / `sz{code}`），腾讯无此市场或失败再落 Yahoo。
- 腾讯数据比 MongoDB 更新时，写回 MongoDB（`_write_bars_to_mongo`，docstring/log 改为「远程兜底获取的 bars（腾讯/Yahoo）」保持来源中立）。
- 沿用原有 `source` / `stale` / `stale_reason` 标记逻辑，下游无感。

## 怎么验证

对 5 只真实持仓逐一取数，确认来源正确、无 Yahoo 403：

- `00700` → tencent 0.32s；`01810` → tencent 0.12s；`560860` → tencent 0.14s；`600941` → mongodb 0.00s（A 股已在库，直接命中）；`603986` → mongodb 0.00s。
- 不再出现 Yahoo 403 等待。

## 局限 / 待办

- 腾讯接口无鉴权、非官方 SLA，量级上仍是「兜底」定位；A 股优先命中 MongoDB 日线缓存，港股/ETF 才走腾讯。
